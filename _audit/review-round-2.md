## New issues found in changed files

### N1. MINOR — `bullet_target_words` still not enforced

The audit flagged this in B8. It is still not enforced. Adding the warning is non-trivial because Claude has to count words after generation and before the JSON is produced. The fix would be a small post-generation check in `apply.md` Step 2.

**Decision:** Leave for round 3 if there is one, or document as a known limitation.

### N2. MINOR — `older_roles_treatment: omitted` is supported in the spec but not in the artifact

The CV artifact renders early_career when `early_career` items are present and the section is in `section_order`. There is no early_career filter based on `older_roles_treatment`. If a user sets `older_roles_treatment: omitted` and includes early_career in their section_order, the artifact still renders them.

**Decision:** Treat as documentation: `older_roles_treatment` documents intent, the user removes `early_career` from `section_order` if they want roles omitted. Update CONTRIBUTING.md.

### N3. MINOR — `tense_current` and `tense_prior` removed from spec but onboarding files still mention them

The onboarding files that I updated removed `tense_current`/`tense_prior`. ✓ Fixed.

### N4. MINOR — Apply.md now references `[id: ...]` profile.md syntax in the parse instructions

The parse instructions in apply.md use both new `[id: ...]` syntax and old `**r1** |` references in some sections. Re-checking the file...

(After re-read) — apply.md's "How to read profile.md" section uses `[id: r1]` in two places and `**r1**` in zero places. Consistent. ✓

### N5. MAJOR — The CV artifact's `tense_current` / `tense_prior` fallbacks no longer exist; nothing breaks but the schema removed two fields

Verified the artifact does not reference `tense_current` or `tense_prior` anywhere. ✓ No regression.

### N6. MINOR — Hard rule "No em dashes" in apply.md mentions both — and –, but the en dash (–) is sometimes a legitimate character

The voice tripwire's hard rule says: "No em dash characters anywhere (— or –). The hyphen `-` is fine." The en dash (`–`) is sometimes used in date ranges in some markets. Banning it in voice rules and dates is overzealous.

**Decision:** Soften the hard rule to em dash only (`—`). Update apply.md.

### N7. MINOR — README's "What to read next" assumes the user can find sub-folder paths

README says "open the right onboarding file (`onboarding/onboard-executive.md`...)". A non-technical reader on Windows might not realise these are paths inside the github-release folder.

**Decision:** Acceptable — the same reader has to navigate folders to download the toolkit. Documented in USAGE.md's "What you need."
